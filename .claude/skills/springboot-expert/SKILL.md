# Spring Boot Best Practices

## Architecture & Design
- **Layered Architecture:** Strictly adhere to the standard multi-tier architecture (Controller -> Service -> Repository).
- **Fat Services, Thin Controllers:** Keep business logic exclusively in the Service layer. Controllers should only handle HTTP routing, validation, and request/response mapping.
- **DTO Pattern:** Use Data Transfer Objects (DTOs) for incoming requests and outgoing responses. Never expose raw Entities directly via REST endpoints.
- **Dependency Injection:** Use Constructor Injection for mandatory dependencies rather than `@Autowired` on fields, facilitating easier unit testing and immutability.

## REST API Guidelines
- **Naming Conventions:** Use plural nouns for resources (e.g., `/api/users` instead of `/api/user`).
- **Standard HTTP Methods:** Utilize `GET` (read), `POST` (create), `PUT` (update), `PATCH` (partial update), and `DELETE` (remove) correctly.
- **Status Codes:** Return standard HTTP status codes (e.g., `201 Created` for POST, `404 Not Found` for missing resources, `400 Bad Request` for validation errors).
- **Versioning:** Implement API versioning (e.g., `/api/v1/resource`) from the start on new services. *This repo's existing endpoints are unversioned* (`/api/companies`, `/api/admin/...`, etc.) — match that convention on new endpoints here rather than introducing a `/api/v1` prefix inconsistently.

## Data Access (JPA / Hibernate)
- **Schema ownership (this repo):** `spring.jpa.hibernate.ddl-auto` is `validate`/`none` in every environment — the schema is hand-migrated via SQL against Supabase Postgres, not generated by Hibernate. Add/alter columns in a migration, then update the `@Entity` to match; never rely on Hibernate to create or change schema.
- **Pagination:** Always implement pagination (`Pageable`) for endpoints that return collections to avoid memory and performance bottlenecks.
- **N+1 Query Problem:** Be mindful of the N+1 problem. Use `@EntityGraph` or `JOIN FETCH` for eager fetching of related entities when necessary.
- **Transactional:** Use `@Transactional` at the Service level to ensure database operations maintain ACID properties.

## Security
- **Authentication:** Use Spring Security (JWT, OAuth2) for securing endpoints.
- **Validation:** Use `spring-boot-starter-validation` (e.g., `@NotBlank`, `@Size`, `@Valid`) on Controller parameters to catch bad data early.
- **CORS:** Configure Global CORS appropriately using a `WebMvcConfigurer` to allow authorized frontends (e.g., the Next.js app) to consume the API.

## Exception Handling
- **Global Exception Handler:** Use `@RestControllerAdvice` and `@ExceptionHandler` to globally handle exceptions and translate them into consistent JSON error responses.
- **Custom Exceptions:** Create custom runtime exceptions (e.g., `ResourceNotFoundException`, `UnauthorizedException`) instead of throwing generic errors.
